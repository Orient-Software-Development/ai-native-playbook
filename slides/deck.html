Act 0 · The problem02 / 24

One prompt. Two programs. One is silently wrong.

Prompt, run twice, identical both times: “Write a Python function median(nums).”

✓ correct
def median(nums):
    s = sorted(nums)
    n = len(s)
    mid = n // 2
    return s[mid] if n % 2 \
        else (s[mid-1] + s[mid]) / 2
✗ silently wrong
def median(nums):
    nums.sort()      # mutates caller
    return nums[len(nums) // 2]


    # never averages the two middles
median([3,1,2]) → both give 2 ✓  (the quick test passes) median([1,2,3,4]) → 2.5 vs 3 ✗

Same prompt. No typo, no bad luck. The tool is allowed to hand you either — and the broken one looks cleaner.

Act 1 · Why the output is random03 / 24

An LLM samples the next token — it doesn't retrieve an answer.

A program returns the same output for the same input. An LLM returns a distribution — sampling (temperature, top-p) picks one. Non-determinism isn't a defect bolted on; it's the mechanism.

Act 1 · Why the output is random04 / 24

“But I set temperature to 0.” Still not deterministic.

The randomness leaks from batch size (server traffic), and GPU kernels aren't batch-invariant — so it's partly outside your control even in principle. You can't make the model reliable by configuring the model.

Act 1 · Why the output is random05 / 24

So don't reduce the randomness — constrain the output space.

The question isn't “how do I make it deterministic?” It's “how do I scope the output so the variance lands in an acceptable range?” That discipline has a name — harness engineering.

The whole game, in one equation.

Agent=Model+Harness

Act 2 · Example 1 — Context08 / 24

The cheapest, highest-leverage harness: a guide file.

AGENTS.md
## Architecture (non-negotiable)
- API routes (src/api/**) MUST NOT contain business logic.
  They call functions in src/product/**. A lint rule enforces this.
## Testing
- Run `npm run check` before you claim done.
- NEVER weaken or delete an existing test to make a build pass. Fix the code.
## Conventions
- Money is Decimal, never number. Dates are UTC ISO-8601.

Each line exists because something once went wrong — the “NEVER delete a test” line, because an agent once did exactly that. “Every line in a good AGENTS.md should trace back to a specific thing that went wrong.” Grow it; don't design it.

Act 4 · Spec-Driven Development18 / 24

Why “factory”? The line, not the worker, guarantees quality.

A factory makes consistent goods from variable workers by engineering the line around them. The agent is the worker; the spec, tests and gates are the line. You become the line manager.

Ford's breakthrough wasn't faster workers — a standardized line with inspection yields reliable output from ordinary, variable workers. We can't make the model reliable, so we make the line reliable.

Red-first is the only honest signal. Tests written after the code just certify “whatever happened to happen.” Write them before, and the agent optimises toward correct behaviour — not toward passing. TDD stops being best-practice and becomes a safety system.

Act 7 · Guard against drift23 / 25

After you ship, two things quietly drift.

Sensors so far grade a single change. But some rot no single change causes — it accumulates. Two kinds, each needing a feedback sensor that runs on a clock, not just per-PR.

Spec drift inferential

Code evolves; the committed spec doesn't move with it. The contract quietly becomes fiction — and a spec nobody re-checks stops being a contract.

Sensor → a scheduled audit re-reads each spec against the code it governs. Any gap is a defect in one of the two: the code regressed, or the spec went stale.

Architecture drift computational

The system's shape erodes one PR at a time: a forbidden import creeps in, a layer is bypassed, coupling grows.

Sensor → fitness functions assert the shape — “clients must not import services”, dependency direction, p95 < 200ms — and a drift gate makes divergence block the merge.

Same computational-first rule as Act 3: the cheap deterministic check guards the shape; the pricier inferential audit guards the intent.

Act 8 · Land it24 / 25

You can't control the model. You can engineer everything around it.

Chasing the next model release is the lever everyone shares. Engineering your harness — and driving it with a spec and tests — is the lever only you own.
